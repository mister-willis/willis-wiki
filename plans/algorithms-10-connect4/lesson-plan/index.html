    Lesson Plan — Connect4

    Planbook Fields

    Lesson (Day 1):

    Direct instruction with slides launching the Connect4 project: students will write a Python library that plays Connect 4 in a class tournament. Covered: the game's rules, the board as a 2D list, and the four required function signatures the tournament program calls (make_move, check_move, check_win, get_name). Lab: students begin the written natural-language algorithm for their make_move strategy in their notebooks. Scored 0–4 on the rubric printed in the assignment when the project is submitted.

    Lesson (Day 2):

    Brief recap of the tournament flow (opponents referee each other's moves), then a work session: students finish their make_move algorithm description, create their library file named per the spec, and implement get_name and a first version of make_move. Deliverables accumulate toward the project submission after the unit-testing lab.

    Standards: AP CSP AAP-1.D, AAP-2.A, AAP-3.C, CRD-2.J; AZ CS HS.AP.M.1, HS.AP.M.2, HS.AP.V.1, HS.AP.PD.3

    Learning Objectives

    Students will be able to:

    • Represent a Connect 4 board as a 2D list and read any cell from it.
    • State the four required function signatures and what each must return.
    • Describe a make_move strategy as a precise natural-language algorithm.
    • Explain why the tournament demands exact names, arguments, and return values from a library it imports.

    Standards Alignment

    Code Standard (abbreviated) Why it's defensible here
    AAP-1.D Develop data abstraction using lists to store multiple elements. The board state is a 2D list of "-", "R", "Y"; every function in the library reads or reasons about it.
    AAP-2.A Express an algorithm using sequencing without a programming language. The make_move algorithm description is a graded deliverable and explicitly forbids Python code.
    AAP-3.C Develop procedural abstractions by writing procedures with parameters and returns. Four functions with specified parameters and return values, written to a published interface.
    CRD-2.J Identify inputs and expected outputs to check program correctness. The required main() test section: students invent boards and illegal arguments and state what each function should return.
    HS.AP.M.1 Decompose problems into components using procedures and modules. The game is decomposed into move-making, move-checking, and win-checking functions inside one module.
    HS.AP.M.2 Use independent but interrelated programs to develop artifacts. The library is imported and driven by a separate tournament program — two programs, one interface.
    HS.AP.V.1 Use lists to generalize instead of repeated simple variables. One 2D list replaces forty-two individual cell variables; make_move loops over it rather than naming cells.
    HS.AP.PD.3 Document design decisions using text in developing complex programs. Partial: the written make_move algorithm documents the design before code exists — text only, per the assignment.

    Materials & Setup

    • slides.pptx (this folder) loaded and tested.
    • Notebooks — the make_move algorithm draft starts on paper.
    • Python environment students used in the data-structures unit; a physical Connect 4 set (or an online version projected) helps the rules land in two minutes instead of ten.
    • The tournament program is not needed yet — it appears at tournament time. Say so, or someone will spend the period hunting for it.

    Slides & Direct Instruction

    The deck (8 slides, speaker notes on each) runs: tournament hook (your code plays, you watch) → game rules and the 69 winning lines → the board as a 2D list, with state[row][col] reading practice → the four required signatures as a contract → why "precisely" is the whole ballgame (dark slide: one misspelled name forfeits games) → your turn: read a board and pick a move by hand → referees who play (your opponent's functions police your moves) → mission slide. Day 1 stops after the practice slide; Day 2 opens on the referee slide. Questions worth asking:

    • "Tic-tac-toe last unit had 8 ways to win. How many does Connect 4 have?" (69 — which is why nobody checks them ad hoc; that's where next lab's helpers come in)
    • "Which row of the 2D list is the top of the board?" (row 0 — and gravity fills from row 5 up; half the unit's bugs are this fact, backwards)
    • "Why does the tournament call your opponent's check_move on your move?" (nobody referees themselves; a sharp referee wins games its make_move didn't earn)

    Pacing — Two 51-Minute Periods

    Day 1

    Minutes Segment What happens
    0–4 Settle + do-now On the board: "From tic-tac-toe: how did we store a 3×3 board in Python?" One-sentence answer in notebooks — the 2D list carries straight over.
    4–20 Slides Rules, state, signatures. Play one fast physical game while narrating what a library would have to decide each turn.
    20–26 Practice Slide 7's board-reading exercise: given a printed state, every student writes the column their library should play, then defends it to a neighbor.
    26–46 Lab Notebook work: draft the make_move algorithm in numbered natural-language steps. Circulate — the common failure is writing Python with the colons removed.
    46–51 Wrap Cold-close: one student reads a step of their algorithm; class judges whether a literal robot could follow it. Preview: "Tomorrow you start the library those steps describe."

    Day 2

    Minutes Segment What happens
    0–4 Settle + do-now "Your opponent proposes column 9. Which of your functions catches it, and what does it return?"
    4–12 Slides Recap on the referee slide; walk the tournament flow start to finish once.
    12–44 Lab Create the library file (first name, lowercase), implement get_name and a first make_move, finish the algorithm write-up. Fast finishers start thinking about check_win — next lab's helpers will meet them there.
    44–51 Wrap Ask for one legal-move strategy simpler than "pick a random legal column" (there isn't one — that's the floor). Preview: "69 winning lines. Next lab we write four small functions that check all of them."

    ELEOT: The 20-Minute Window

    Item The move in this lesson
    A.2 Every student competes with the same required interface and the same board representation — the contest is strategy, not resources.
    B.1 The tournament is the stated bar: students can articulate exactly what their library must survive, because the flow is on slide 6.
    B.4 Designing a move strategy is analysis and synthesis — the algorithm draft forces choices, not recall.
    C.2 Day 1 wrap collects algorithm steps aloud and judges them for followability, not correctness — a safe first showing of unfinished work.
    C.3 The assignment's exact-signature warning and Game State examples let stuck students self-rescue; neighbors defend column choices in the Day 1 practice.
    D.2 The physical game on the desk is the real-life referent; the tournament mirrors how real software is called by code its author never meets.
    D.3 Minutes 20–46 both days are hands-on: reading boards, drafting algorithms, building the library file.
    E.1 Rotating notebook check-ins during Day 2 lab; the algorithm draft is the first checkpoint of the four-lab project.
    E.4 Rubric printed in the assignment; ask one student on rotation what separates a 4 from a 3 (an algorithm another programmer could implement unaided).
    F.3 Both days move slides → practice → lab on the clock table; the handoff is "understand your mission for today?"
    G.2 Students build an original competitive program in Python — two days of original-artifact work in the tool.

    Common Student Errors

    • Writing the algorithm as pseudo-Python — if col_full: skip — instead of sentences. Have them read it aloud; if it can't be spoken, it isn't natural language.
    • Treating row 0 as the bottom of the board. The printed examples in the lab put row 0 on top; a make_move built on the wrong gravity plays legally and loses constantly.
    • Renaming functions "more clearly" (makeMove, chooseColumn). The tournament imports by exact name — the lab's warning callout says forfeits, and it means it.
    • Returning the wrong type from make_move — "3" instead of 3. The tournament does not coerce strings.
    • Planning a grand strategy before a legal one. The floor is "any legal column, every time, for any board"; the ceiling can wait until the floor exists.

    Assessment & Evidence

    • Deliverable: the written make_move algorithm (no Python code) in the notebook, and the started library file — both submitted with this assignment after the unit-testing lab (see Turn It In).
    • Score: 0–4 holistic rubric in the assignment. A 4 requires exact signatures, graceful recovery from illegal arguments, and an algorithm description another programmer could implement without asking questions.
    • Look-fors during check-ins: numbered steps with action verbs, no code in the algorithm draft; the file named correctly (lowercase first name); make_move that never proposes a full or out-of-range column.
