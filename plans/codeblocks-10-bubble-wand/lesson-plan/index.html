    Lesson Plan — Bubble Wand

    Planbook Fields

    Lesson (Day 1 — Shapes and holes, steps 1–15):

    Direct instruction with slides: CAD by code — in Tinkercad Codeblocks a program draws the 3D model, and pressing Play runs it. Students create and name the project, then build the wand's ring from a hole cylinder, a solid cylinder, and a hole tube, grouped into one shape. Progress is checked against the lab's block figures and "your screen should look like this" previews.

    Lesson (Day 2 — Variables, steps 16–28):

    Students create four named number variables (InnerRadius, Thickness, OuterRadius, Overflow), gather the Set blocks at the top of the program, and rewire every shape parameter to use a variable instead of a plain number (hole heights become Thickness + 1). The wand looks identical afterward, which is the point of the closing discussion. Each section is labeled with a comment block.

    Lesson (Day 3 — Math blocks, steps 29–46):

    Brief direct instruction on order of operations with blocks: two math blocks that read the same and compute differently. Students build the handle (cylinder, rotate, move) and the torus base, with every position equation a single two-slot math block; the middle steps get their own variables (Length, HalfLength, HandleEnd). Finish with the whole wand in one color.

    Lesson (Day 4 — Loops and printing, steps 47–64):

    Direct instruction with slides on loops: the Count with block repeats a box and a rotation to draw a ring of ridges no one would place by hand. Students name the ridge sizes as variables, add the ridge loop, trim the centers with a hole cylinder sized by CutRadius and CutHeight, thicken the entire wand by changing Thickness once, and export the design as an .STL submitted in Google Classroom. Scored 0–4 on the rubric printed in the assignment.

    Standards: AZ CS 6.AP.V.1, 6.AP.M.1, 6.AP.PD.5, 6.AP.C.1, 6.AP.PD.3

    Learning Objectives

    Students will be able to:

    • Build a 3D model from code blocks and run the program with Play.
    • Create named number variables and use them as shape parameters.
    • Combine variables with math blocks to compute a size or position, one operation per block, with the operands of - and / in the right order.
    • Explain why a math block inside a math block is computed first, and avoid it by naming the middle step.
    • Label each section of a program with a comment that says what it builds.
    • Use a counting loop to repeat a shape with a changing rotation, and explain what the loop variable i is and where its values come from.
    • Rebuild an entire design by changing one variable's value.
    • Export a Tinkercad design as an .STL file for 3D printing.

    Standards Alignment

    Code Standard (abbreviated) Why it's defensible here
    6.AP.V.1 Identify variables that represent data types and perform operations on their values. The heart of the lab: twelve named variables replace every plain number, and math blocks operate on them (OuterRadius + Overflow, Length / 2, InnerRadius - RidgeWidth). The no-spaces naming rule is the standard's naming-conventions point, and the Day 4 payoff (change Thickness once, everything rebuilds) is the operation-on-values idea made visible.
    6.AP.M.1 Decompose problems into parts to facilitate design and review. The wand is built as three commented sections, ring, handle, and base, each written and tested separately before the next begins, and the ridges are added to the ring section without touching the others.
    6.AP.PD.5 Document programs to make them easier to follow, test, and debug. Steps 27–28, 31, and 41 require a comment block naming what each section builds; documentation is a graded checklist item, not a suggestion.
    6.AP.C.1 Design programs that combine control structures, including nested loops and compound conditionals. Partial: the ridge loop is a single Count with loop containing a box and a rotation driven by i, a real counting control structure, but nothing nested or conditional yet.
    6.AP.PD.3 Test programs using a range of inputs and identify expected outputs. Partial: students change the loop step (10 → 12) and Thickness (1 → 2), predict the result, and verify against the lab's expected screenshots, a small but genuine input-range test.

    Materials & Setup

    • slides.pptx (this folder) for Days 1–3 and slides-loops.pptx for Day 4, loaded and tested. The Day 1–3 deck predates the no-nested-math rewrite and still shows the old handle equation on its build-plan slide; skip or fix that slide before teaching.
    • Tinkercad class accounts. Verify every student can sign in before Day 1; a login problem eats the whole period for that kid.
    • Google Classroom assignment open on Day 4 to receive the .STL files.
    • Notebooks.
    • The lab is four days in the same design. Tinkercad saves automatically, so there is nothing to collect between days; the "Day N starts here" boxes in the lab show each day's expected starting state, and the plan's look-fors below say what a screen should show by each day's end.

    Slides & Direct Instruction

    The Day 1–3 deck (8 slides, speaker notes on each) runs: title → drawing by hand vs. programming the drawing → the three shape blocks and the Play button → a dark big-number beat (five named numbers control the whole wand) → variables as names for numbers → "your turn" prediction pair → the build plan (comments, handle, base) → mission slide. Day 1 stops after the Play demo; Day 2 opens with the variables and prediction slides; Day 3 opens with the build-plan slide and the lab's order-of-operations box on the projector.

    The Day 4 deck (8 slides) runs: title → the tedious job (fifteen ridges by hand vs. one loop) → anatomy of the Count with block → a dark big-number beat (one box block, a full ring of ridges) → predict-the-loop practice pair → the one-change rebuild (Thickness 1 → 2) → what an .STL is and how to export → mission slide.

    Questions worth asking:

    • "If I want the ring twice as thick, how many blocks do I have to touch?" (Day 1, before variables: several; Day 2, after: one. That's the sales pitch.)
    • "Why won't Tinkercad accept Inner Radius as a name?" (no spaces; the computer would read it as two things)
    • "The computer ignores comments completely. So who are they for?" (future you, and anyone helping you debug)
    • "These two blocks say the same words. Which one is 25 and which is 20?" (the inside block runs first; you can only tell by the outlines, which is why we give the middle step a name instead)
    • "Who creates the variable i? What's in it on the third trip through the loop?" (the loop makes it; the third trip is 20 when counting by 10)
    • "Why does the loop stop at 179 and not 359?" (each box crosses the whole ring; by 180 degrees you've drawn both sides)
    • "If we count by 12 instead of 10, do we get more ridges or fewer?" (fewer: bigger steps, fewer stops)

    Pacing — Four 51-Minute Periods

    Day 1 — Shapes and holes (steps 1–15)

    Minutes Segment What happens
    0–4 Settle + do-now On the board: "You need 15 identical windows on a Minecraft build. What's the worst way to do it? The best?" Plant the seed for Day 4: let the machine repeat itself.
    4–16 Slides Slides 1–3; do the Play-button demo live in Tinkercad: drop a cylinder, run it, break it, fix it. Narrate misclicks cheerfully.
    16–44 Lab Steps 1–15: sign in, create, rename, then the ring. Sign-in and project setup take longer than they look; budget for it. The block figures are the answer key, so train them to compare before raising a hand. Step 14 is the concept: holes don't cut until Group Selection.
    44–51 Wrap Screen check against the step 15 preview. Cold-close: "I want a bigger wand. How many numbers would you have to change?" (several, and they all have to agree). Preview: tomorrow, one number.

    Day 2 — Variables (steps 16–28)

    Minutes Segment What happens
    0–4 Settle + do-now Open Bubble Wand, press Play, compare with the "Day 2 starts here" picture. Anyone who isn't there finishes Day 1 first.
    4–16 Slides Slides 4–6: five named numbers control the whole wand, variables as names for numbers, the prediction pair.
    16–44 Lab Steps 16–28: create four variables, gather the Set blocks at the top, rewire every parameter, then the two comments. Rotation check: no plain number left in a shape parameter, and every Set block above the ring.
    44–51 Wrap Cold-close: "The wand looks exactly the same as it did yesterday. What did we actually gain?" Collect answers, confirm nothing yet. Preview: tomorrow the wand grows a handle, and the math gets interesting.

    Day 3 — Math blocks (steps 29–46)

    Minutes Segment What happens
    0–4 Settle + do-now "Write one sentence: what does a variable do for your program?" Compare with a neighbor. Screen check against the "Day 3 starts here" box.
    4–14 The nesting talk Slide 7 (build plan: handle, then base, each with a comment). Then the lab's order-of-operations box on the projector: two blocks that both read InnerRadius + Length / 2; ask for the two answers (25 and 20) before revealing. The rule: the inside block goes first, so we don't nest; the middle step gets a variable.
    14–44 Lab Steps 29–46. HalfLength and HandleEnd are the new idea; the check during rotation is that every math block holds exactly two things. Rotate-before-move on the handle is where hands go up.
    44–51 Wrap Checkpoint check: ring, handle, base, one color. Cold-close: one student explains what the Move block's equation computes. Preview: "Tomorrow, one loop draws fifteen ridges, and then we print it."

    Day 4 — Loops and printing (steps 47–64)

    Minutes Segment What happens
    0–4 Settle + do-now On the board: "Your wand needs 15 evenly spaced ridges. Estimate: how long to place them by hand? How many mistakes?" Screen check against the "Day 4 starts here" box.
    4–16 Slides Day 4 deck, slides 1–6; work the loop-prediction slide together before releasing. It's the whole concept check.
    16–40 Lab Steps 47–61: ridge variables and loop, center trim, thickness change. Step 57's InnerRadius - RidgeWidth is the day's order-of-operations moment; ask what happens if the two are swapped before anyone builds it. Step 58 is where hands go up: the hole comes after the loop and before Group Selection.
    40–47 Export + submit Steps 62–64: Share → .STL → Google Classroom. Watch for downloads-folder confusion. Students who finish early customize with the tip at step 61.
    47–51 Wrap Cold-close: "What did the variable Thickness just save you?" Preview: "Next design has trucks, axles, and wheels that snap on, and the training wheels come off."

    ELEOT: The 20-Minute Window

    Item The move in this lesson
    1 Do-nows and cold-closes each day have students predicting before pressing Play: the two answers to the nesting question, the ridge count for a new step value.
    3 Day 3's nesting talk and Day 4's "why stop at 179?" have students reasoning about blocks and geometry together, with the outlines and the preview as evidence.
    5 The lab's block figures and "your screen should look like this" previews are the self-check at every rung; the "Day N starts here" boxes are the organizer for where to begin.
    7 Four days building an original 3D artifact in a browser-based CAD tool, ending in a file that goes to a real printer.
    9 Day 2's cold-close ("the model looks identical, what did we gain?") demands analysis of an invisible improvement; Day 4's step change (10 → 12) is a prediction, not a recipe.
    10 Variables named for real dimensions mirror how CAD work parameterizes parts, and the .STL has stakes because it prints. Say both out loud.
    11 The step ladder climbs from drag-a-cylinder to a loop rotating a box by i, with a bounded fix for every predictable stumble (below).
    12 From step 4 on, students drive the lab doc themselves; the teacher demos once a day and gets out of the way.
    16 Neighbors are the stated second resort before a hand goes up; the preview screenshots let stuck students self-rescue.
    18 Transitions are on the clock tables; the slides-to-lab handoff each day is one sentence, "understand your mission for today?"
    22 The 0–4 rubric is printed in the assignment; ask one student mid-rotation what separates a 4 from a 3 (no stray plain numbers, no nested math).
    24 Each day's cold-close has a learner verbalizing the concept in their own words: what a variable buys you, what the Move equation computes, what Thickness just saved them.

    Common Student Errors

    • Naming a variable with a space (Inner Radius). Tinkercad refuses it; the lab's warning box covers it, but expect it anyway.
    • Editing the number on the shape instead of dragging the variable in. The model works today and breaks on Day 4 when Thickness changes and one piece stays skinny. That's the rubric's 3, not a 4.
    • Forgetting to press Play after a change, then reporting "it didn't work." The program only runs when told to.
    • Rotate before Move confusion on the handle. Doing the Move first rotates the handle around the wrong point. Order of blocks is order of operations.
    • A math block dropped inside another anyway (a student who builds InnerRadius + Length / 2 or Thickness / 2 straight from memory). Have them read the outlines aloud, then pull the inner block out into its own Set variable; the lab's rule is one operation per block, and the rubric checks it.
    • A getter in the wrong slot (RidgeWidth - InnerRadius instead of InnerRadius - RidgeWidth). Harmless for + and *, wrong for - and /: a negative cut radius, so the trim does nothing and the ridge stubs stay. The lab's warning box names it; the fix is swapping the two slots.
    • The Rotate block outside the loop. One ridge, rotated many times, instead of many ridges. The preview exposes it instantly.
    • Forgetting to drag i into the Rotate block's by slot. Every box lands in the same spot and looks like one thick ridge.
    • The hole cylinder or Group Selection inside the loop. The trim runs every pass and eats the wand.
    • Exporting before pressing Play one last time. The .STL captures the last drawn model, not the blocks.

    Assessment & Evidence

    • Deliverable: the wand's .STL file submitted in Google Classroom on Day 4 (mirrors Turn It In). Days 1–3 are checked on screen during rotations; nothing is collected.
    • Score: 0–4 holistic rubric printed in the assignment ("How It's Graded"). A 4 requires the complete ridged wand from code, every size traced to a variable with no nesting, a comment on each section, one color, and a Thickness change that rebuilds everything.
    • Look-fors by day:
      • Day 1: the four ring blocks in order, hole cylinder first, Group Selection last, and the step 15 preview on screen.
      • Day 2: Set blocks gathered at the top under a Variables comment; no orphan plain numbers in shape parameters; a The ring comment.
      • Day 3: every math block holds exactly two things; HalfLength and HandleEnd set in the Variables section; the student can change Thickness on request and predict what will happen before pressing Play.
      • Day 4: box and rotate nested inside the Count with block; i visibly in the rotation; the hole and Group Selection after the loop; the student can predict the ridge count for a new step value.
